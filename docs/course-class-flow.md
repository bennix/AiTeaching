# 课程、班级与学生可见内容

## 数据关系

- `students.courseName + students.className`：选课名单建立的课程与班级目录。课程目录不依赖 AI 是否整理完成。
- `lessons.courseName + lessons.classNames`：一个教学周属于一门课程，可以关联该课程的多个班级。`className` 保留为旧格式兼容字段。
- `exercises.lessonId`、`materials.lessonId`：习题与课件继承教学周的课程和班级范围。习题还需要 `published: true`；个性化题还需要匹配 `targetStudentId`。
- `submissions.exerciseId` 与 `attendance.lessonId`：分别将作答和签到连回课次，按 `studentId` 记录学生。
- 课程与班级名称比较统一忽略无意义空白、全半角和重复括号。班级选择必须同时限定课程，不能仅凭班级名关联。

## 操作流程

1. 导入选课单，建立课程、班级及学生名单。学生登录页立即显示该课程和对应班级。
2. 导入教案时选择适用班级。同课程只有一个班级时自动选中；有多个班级时要求明确选择。可以在没有名单时先准备教案，但未关联教案不会作为班级内容展示。
   新建的未关联教案记录为 `classAssociation: pending`。以后导入该课程名单时，只有一个匹配班级则补齐关联；一次导入多个班级时保持待关联。手工解除或删除班级产生 `detached` 状态，不会自动转给其他班级。
3. 教案详情中的“关联班级”可独立保存关联，不必重新生成课件。生成课件时不得以空选项覆盖现有关联。
4. 教学方案完成后，关联班级能查看方案及课件；教师发放习题后学生才能看到习题。补生成题库不隐藏已有教学内容。
5. 删除班级时删除对应名单并解除教案关联；残留教案不能重新建立已删除的课程/班级目录。
6. 学生登录弹窗每 15 秒更新课程目录，保留仍有效的选择；只剩一个课程或班级时自动选择。

## 桌面应用与局域网服务

整个 Electron 进程只初始化一次服务和 `JsonStore`。关闭 macOS 窗口时服务继续运行；点击 Dock 重开窗口复用原服务和端口。重复启动应用通过 single-instance lock 聚焦现有窗口。退出应用时关闭服务。

`electron/lib/teaching-catalog.js` 集中维护课程班级目录、教案班级兼容读取和待关联教案的补齐规则；学生目录、关联校验与名单导入使用同一套关系规则。

2026-09-07 的问题由两处共同导致：重开窗口创建第二份服务/内存数据，旧服务保留已删除班级；生成课件时空班级选择覆盖了教案关联。实际观察到同一进程监听 5000、50036，并分别返回旧目录和空目录。

## 回归验证

运行 `npm test`。`main-lifecycle.test.js` 验证关闭、并发重开和重复启动不会创建第二个服务；`catalog-flow.test.js` 验证先建名单、关联教案、只显示已发放题、补题期间可见、空关联拒绝、班级删除及单班自动关联。

本次沿用现有数据结构，并未实现独立的学生多课程选课关系表；当前学生导入仍以学号更新一条学生记录。若要让同一个学生同时保留多个课程的独立选课记录，需要单独迁移该结构。
